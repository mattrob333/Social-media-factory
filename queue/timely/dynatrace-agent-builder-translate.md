Dynatrace just launched a no-code Agent Builder.

Anyone on your ops team can now spin up an autonomous agent to triage incidents, restart services, and run remediations across AWS/Azure/GCP. No engineering ticket. No security review. No identity provisioning.

This is the future of ops automation. It's also the fastest path to an NHI sprawl problem you can't inventory.

Every one of those agents is a non-human identity with permissions your SRE chose in a UI. If the agent's task outlives its usefulness — and it will — those credentials stay live. If the agent makes a bad call in a production environment — and it will — the audit trail says "service account" with no named owner.

Dynatrace's launch is the right product. The governance gap that comes with it is the market nobody is shipping.

If you're adopting no-code agent builders, before you deploy the second agent: name an owner, set least-privilege by default, and make sure the rollback plan is as easy as the build.

The easy part is building the agent. The hard part is building the one that can't hurt you.
